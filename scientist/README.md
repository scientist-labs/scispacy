# Scientist scispaCy releases

This public fork carries upstream's merged but unreleased dependency fix:
[allenai/scispacy#559](https://github.com/allenai/scispacy/pull/559) selects official
`nmslib>=2.1.2` instead of `nmslib-metabrainz`. The baseline is upstream commit
`eacccd4ef3e7ef13d4aa35700e718bd4318ded17`, which also includes
[#556](https://github.com/allenai/scispacy/pull/556)'s newer-SciPy TF-IDF fix.
This is not an independently reimplemented ANN backend. Upstream attribution
and the Apache-2.0 license are preserved.

The fork also bounds `typer<0.26`: spaCy 3.8.14 imports Click directly, but
Typer 0.26+ stopped depending on Click. An otherwise successful fresh wheel
installation fails on `import spacy` without this compatibility bound. It is
part of the wheel's runtime metadata, not a smoke-only extra installation.

## Branches and identity

- `main`: upstream mirror. Do not land Scientist changes here.
- `scientist-main`: default integration branch; target all Scientist PRs here.
- Release tags: `v<upstream-version>-sci.N`, beginning at `v0.6.2-sci.1`.
- Python distribution versions: `<upstream-version>+sci.N`, e.g.
  `0.6.2+sci.1`. `-sci.1` is our Git tag spelling, **not** valid Python
  distribution version syntax. The package stays named `scispacy`.
- `N` is globally increasing across Scientist tags, including after an upstream
  version bump. It is not a lexical comparison, and never resets for a new
  upstream version. Tags are never overwritten. Failed releases may consume a
  number and leave a gap.

`scispacy/version.py` retains upstream's base version on integration branches.
CI adds the local-version suffix in its build checkout; both wheel and sdist
receive the same version. GitHub's autogenerated source archives do **not**
contain that stamp. Consume our versioned wheel/sdist assets instead.

## Assets and architecture support

Each [GitHub Release](https://github.com/scientist-labs/scispacy/releases) contains:

- `scispacy-X.Y.Z+sci.N-py3-none-any.whl` and its source distribution;
- the **unmodified official** nmslib 2.1.2 CPython 3.11 Linux `aarch64` and
  `x86_64` wheels, verified against the source URLs, sizes and SHA256 hashes in
  [nmslib-wheels.json](nmslib-wheels.json);
- native per-architecture qualification reports, `PROVENANCE.json`, and
  `SHA256SUMS` covering every other asset.

**scispaCy is pure Python.** Its universal wheel works on both architectures;
we do not relabel it as an ARM-only wheel. The compiled ARM asset is the
original nmslib wheel, not a Scientist C++ rebuild. Its bundled licensing and
metadata remain unmodified; the manifest attributes the exact PyPI source.

The qualification target is **Linux CPython 3.11 on Debian Bookworm**, using a
pinned multi-arch Python container on native GitHub-hosted amd64/arm64 runners.
There is no QEMU, private reusable workflow, self-hosted runner, AWS credential,
PyPI publishing credential, or private repository dependency. The original
upstream PyPI publishing workflow is disabled for this fork.

A universal wheel does not imply every dependency is available for every
platform or Python version. This release qualifies only the target above;
upstream's Python `<3.13` / NumPy `<2.0` bounds are unchanged.

## Install

In a clean Python 3.11 virtualenv, select an explicit release (example):

```sh
python -m pip install --only-binary=:all: \
  'https://github.com/scientist-labs/scispacy/releases/download/v0.6.2-sci.1/scispacy-0.6.2%2Bsci.1-py3-none-any.whl'
```

This fetches remaining dependencies, including official nmslib, from PyPI. To
use the mirrored nmslib asset instead, download the release's **matching
architecture** wheel and pass both wheel paths to the same pip invocation.
Verify downloaded assets against `SHA256SUMS`; retain the source commit and
artifact hashes in downstream lockfiles. Do not install `nmslib-metabrainz`
alongside `nmslib`, since both provide the same import.

This is **not a full offline wheelhouse**. Models, RxNorm/UMLS data and other
runtime dependencies are not release assets. The recorded
[qualification constraints](constraints-cp311.txt) are not a replacement for a
consumer's frozen dependency lock. A downstream project must select this fork's
source and refresh its lock; preinstalling nmslib does not override an existing
lock selecting published upstream scispaCy and MetaBrainz.

## CI and publication

[Scientist wheels](../.github/workflows/scientist-wheels.yml) runs for PRs into
`scientist-main`. It tests version allocation and artifact validation, builds
one wheel/sdist, then installs that **same wheel** with binary-only dependency
installation on both native architectures. A fresh virtualenv prevents a
source checkout or preinstalled MetaBrainz package from hiding errors.

The smoke check uses the public upstream test KB, creates and serializes its
sparse ANN index, reloads it via scispaCy, queries it, and checks empty/OOV
queries, a blank spaCy pipeline and the spaCy `info` CLI. Network connections are prohibited during
the smoke. A green check is **not** a claim that a downstream biomedical model
or redaction pipeline has been validated: consumers still need model/KB and
end-to-end application tests. In particular, upstream 0.5.4 model packages
have spaCy version constraints that need separate attention.

A push to `scientist-main` (normally a merged PR), or a manual run **on that
branch**, qualifies and releases the next version. Only the final publish job
has `contents: write`; PR runs never publish. Releases are serialized, and a
run superseded by a newer integration commit skips publication. Both native
jobs must pass; there is no `continue-on-error` or single-architecture release.

Publication reserves a new tag, creates a draft, uploads all assets, downloads
and verifies them, then makes the complete release public. It does not rely on
a token-created tag triggering another workflow. If publication fails after
tag reservation, retain that tag and rerun **all jobs** to get a new number.
An incomplete draft can be deleted manually without deleting/reusing its tag.
Expired/missing Actions artifacts also require rerunning all jobs.

The first release is made when the release-setup PR lands in `scientist-main`.
The `v0.6.2-sci.1` example above is not an assertion that it already exists.

## Local release-tool tests

These tests need Python 3.11+ and no third-party dependencies:

```sh
python3 -m unittest discover -s scientist -p 'test_*.py' -v
python3 scientist/release.py plan
```

Only CI build checkouts should be stamped. Test package builds in a temporary
copy rather than changing the integration branch's upstream version file.
When updating the upstream baseline, review its dependency delta, update the
baseline recorded in `release.py`, and retain the existing global tag counter.
